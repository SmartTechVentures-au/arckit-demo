# ArcKit Demo — The University of Funk

**A worked example of an architecture engagement, governed end to end by
[ArcKit](https://arckit.org/) rather than hand-written.**

This repository is not a blank starter. It contains the complete paper trail of a
real-shaped solution architecture engagement for an Australian university —
principles, requirements, risk register, ADRs, Wardley maps, business case,
research, procurement documents, diagrams and traceability matrices — all
generated by ArcKit running inside [Claude Code](https://claude.com/claude-code),
and all cross-referenced so you can follow a single weakness from a survey
response through to a roadmap line item.

ArcKit is an AI harness that wraps your AI coding assistant. It gates, traces and
provenance-stamps everything the assistant produces, so what comes out is
audit-ready architecture documentation rather than plausible-looking prose.

> ⚠️ **The University of Funk does not exist.** It is a fictional Australian
> university invented for this public demonstration, and every person named in
> these documents is a fictional character. Commercial product names (Blackboard,
> PeopleSoft, Echo360, Turnitin and others) appear illustratively to keep the
> architecture realistic — no claim is made about any real vendor's hosting,
> security or practices.

## How to use this repo

Pick the depth you want:

**1. Just look at the output** — no setup, no API key.

```bash
npm run serve      # → http://localhost:8080
```

That serves the generated documentation site in `docs/`: a governance dashboard,
every artifact rendered with its Mermaid diagrams, and a health scan. It is
static, so you can also open `docs/index.html` directly.

**2. Read the walkthrough** — [`DEMO.md`](DEMO.md) is the guided tour. It explains
the scenario, maps the engagement's nine work packages to the ArcKit commands
that produced each artifact, and includes a live-demo run sheet. Start there if
you want to understand *why* the artifacts look the way they do.

**3. Run it yourself** — open the repo in the dev container (see
[Environment setup](#environment-setup) below), start Claude Code, and drive
ArcKit against the same inputs. `demo-inputs/` holds the six "day one" client
documents the whole trail was generated from, so you can regenerate any artifact
and compare. Useful entry points:

| Command | What it does |
| --- | --- |
| `/arckit:start` | Orientation — recommends a command sequence for your project |
| `/arckit:navigator 001` | Shows what a project has, what's missing, what to run next |
| `/arckit:health` | Scans every project for stale research, forgotten ADRs, orphan requirements |
| `/arckit:graph-report` | Coverage and traceability metrics across all projects |
| `/arckit:build 001 --plan` | Dry-runs the bulk build harness without writing anything |

Running `--plan` first is worth the habit — it shows exactly which files a build
would create or overwrite before it does anything.

## What's in here

```
.
├── DEMO.md            ← the guided walkthrough — read this first
├── demo-inputs/       ← the six client documents everything was generated from
├── docs/              ← generated documentation site (/arckit:pages)
├── projects/          ← the governed artifacts
│   ├── 000-global/            org-wide principles + governance process
│   ├── 001-lt-ecosystem/      the baseline strategy engagement
│   ├── 002-lecture-capture/   procurement spun out of a decision in 001
│   ├── 003-lms-ultra-migration/
│   └── 004-integration-platform/
└── scripts/           ← dev-container helpers and the static server
```

Four working projects sit alongside a shared `000-global` space. Principles are
authored **once** in `000-global` and inherited by every project initialised
afterwards — that inheritance, and the traceability that survives a project
boundary, is the point the demo is making.

The scenario is deliberately unglamorous: no greenfield build, no AI product.
It's the work most architects actually get handed — an estate that grew for a
decade and now needs a defensible rationalisation story.

## Environment setup

The repo was built from
[arckit-template](https://github.com/SmartTechVentures-au/arckit-template), a
VS Code Dev Container with Claude Code and the ArcKit plugins pre-installed.

- **Dev Container** (Python 3.12) with Git, Node, `uv`, `ruff`, `pytest`,
  `pylint`, and the [Marp](https://marp.app/) CLI for slide decks.
- **Claude Code** installed and updated to the latest version (ArcKit needs
  `v2.1.172+`).
- **ArcKit plugins** installed from the
  [`tractorjuice/arc-kit`](https://github.com/tractorjuice/arc-kit) marketplace:
  the core `arckit` plugin plus the `arckit-au` (Australian government) overlay,
  which supplies the Privacy Act 1988 and Essential Eight commands this demo uses.
- A small static **docs server** (`npm run serve` → http://localhost:8080).
- VS Code extensions for Python, Ruff, Copilot, Claude Code, Marp, and Mermaid.

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- [VS Code](https://code.visualstudio.com/) with the
  [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers)
  extension — **or** [GitHub Codespaces](https://github.com/features/codespaces).
- An **Anthropic API key** (and optionally an OpenAI key).

### Getting started

Only needed for path 3 — browsing the generated site needs none of this.

1. Clone the repo:
   ```bash
   git clone https://github.com/SmartTechVentures-au/arckit-demo.git
   ```
2. Copy the env template and fill in your values:
   ```bash
   cp .env.example .env
   ```
3. Provide your API keys. They are read from your **host environment** and
   forwarded into the container (see [`devcontainer.json`](.devcontainer/devcontainer.json)).
   Export them before launching VS Code:
   ```bash
   export ANTHROPIC_API_KEY=sk-ant-...
   export OPENAI_API_KEY=sk-...        # optional
   export GIT_USERNAME="Your Name"     # optional
   export GIT_EMAIL="you@example.com"  # optional
   ```
4. Open the folder in VS Code and choose **Reopen in Container**. The
   `post-create` step installs Claude Code and the ArcKit plugins automatically.
5. Start Claude Code and run an ArcKit command:
   ```bash
   claude
   ```
   Then try `/arckit:start` inside the session to get oriented.

Starting your own project instead of exploring this one? Use
[arckit-template](https://github.com/SmartTechVentures-au/arckit-template) — the
same container without the worked example.

## Configuration

- **`.env.example`** — copy to `.env`; documents the supported variables.
  `.env` is gitignored and must **never** be committed.
- **`.devcontainer/`** — `Dockerfile`, `devcontainer.json`, and the
  `post-create` / `post-start` scripts.
- **`scripts/`** — helper scripts (static server, env loader, Claude installer).

## Security

This is a template — keep secrets out of it. `.env` is gitignored; only
`.env.example` (with placeholder values) is tracked. Never commit real API keys
or personal access tokens.
